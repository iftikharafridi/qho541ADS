Setup & tools

Everything for this module runs on a normal Windows laptop with free software. The core tools are Python (which already contains SQLite and Tkinter) and DB Browser for SQLite.

Teaching recommendation: keep dependencies small

Weeks 1–5 use only the Python standard library. Later weeks may add one small package where it is the sensible choice (for example cryptography for reversible encryption). Each week’s page lists exactly what to install and why. Fewer packages means fewer “it works on my machine” problems when your submission is marked.

Install Python on Windows

  1. Download the latest Windows installer (64-bit) from python.org/downloads/windows.
  2. Run it. On the first screen tick “Add python.exe to PATH”, then choose Customize installation.
  3. Make sure “tcl/tk and IDLE” and “py launcher” are ticked (they are by default). Tkinter needs tcl/tk.
  4. Finish the install, then open a new Command Prompt or PowerShell window and run the checks below.

py --version
py -c "import sqlite3; print('SQLite', sqlite3.sqlite_version)"
py -m tkinter

You should see a Python version (3.11 or newer), an SQLite version (3.35 or newer), and a small Tk window with two buttons. Close it to finish.

py or python?

On Windows the py launcher always finds your newest Python, even if PATH is wrong. On macOS and Linux use python3 instead of py. All instructions on this site work with either.

Create a project folder

Keep each week’s files together and run scripts from inside that folder. The example scripts find their databases relative to their own location, so they work wherever you put the folder. You will not see hard-coded C:\Users\… paths anywhere.


mkdir $HOME\Documents\QHO541
cd $HOME\Documents\QHO541
# optional but good practice: a virtual environment for later weeks
py -m venv .venv
.venv\Scripts\Activate.ps1

PowerShell says “running scripts is disabled”

Run Set-ExecutionPolicy -Scope CurrentUser RemoteSigned once, or use Command Prompt and .venv\Scripts\activate.bat. A virtual environment is not needed for Weeks 1–5.

DB Browser for SQLite

  1. Download the Windows installer from sqlitebrowser.org/dl and install it.
  2. Open Database and choose shop_v1.db (from Week 1 → Resources).
  3. Database Structure shows tables and columns; Browse Data shows rows; Execute SQL runs queries. Press Ctrl+Enter or F5 to run.
  4. On the Edit Pragmas tab check that Foreign Keys is ticked, so foreign keys are enforced while you work.
  5. After changing data, click Write Changes (Ctrl+S). Until you do, the file stays locked and Python may report database is locked.

Run the Week 1 examples

Download the Week 1 files (Week 1 → Resources), unzip them into your project folder, then:


cd %USERPROFILE%\Documents\QHO541\week01
py build_shop_db.py
py explore_shop_v1.py

build_shop_db.py creates shop_v1.db from schema_v1.sql and seed_v1.sql and prints a row count for every table. explore_shop_v1.py runs the worked examples from the lecture.

Run this site locally

The site is plain HTML, CSS and JavaScript with no build step. The SQL playgrounds load a WebAssembly build of SQLite and a database file, and browsers only allow that over http://. Double-clicking index.html opens it as file:// instead, so start a small local web server:


py -m http.server 8000

Then open http://localhost:8000/. Press Ctrl+C in the terminal to stop the server. Everything the site needs is included locally, so it works without an internet connection, which is useful in classrooms with unreliable Wi-Fi.

Troubleshooting

Message or symptomLikely causeFix
'python' is not recognized…Python is not on PATH.Use py instead, or reinstall with “Add python.exe to PATH” ticked.
ModuleNotFoundError: No module named 'tkinter'tcl/tk was not installed.Re-run the installer → Modify → tick “tcl/tk and IDLE”.
sqlite3.OperationalError: no such table: customerPython opened (and created) a different, empty database file, usually because the script ran from another folder.Build paths from the script’s folder with Path(__file__).resolve().parent (as the examples do), and delete the stray empty .db file.
database is lockedAnother program has uncommitted changes open.In DB Browser click Write Changes or Close Database, then retry.
Foreign keys are not enforcedSQLite starts every connection with foreign keys OFF.Run PRAGMA foreign_keys = ON; straight after connecting, every time.
The SQL playground says it could not start SQLiteThe page was opened as a file:// URL.Use py -m http.server as above, or use the published GitHub Pages site.
