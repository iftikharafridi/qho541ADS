The task

Official task (summarised from the brief)

Working as a Database Analyst/Developer, design and implement a database system for a company of your choice (for example a bank, restaurant, online shop, hospital, clothing store or mobile service provider) to keep track of customer, inventory, employee and accounting information. Outline the scenario and client requirements; create a SQLite database to cover the ERD; build an XML database and a Python Tkinter application; and include tests.

The report should start with an Introduction that pulls together and summarises the whole project, including its background and what inspired it. You may use statistics to argue why the project was needed.

Grade descriptors in brief

The brief describes five bands (0–39, 40–49, 50–59, 60–69, 70+) for each part. The main differences between bands:

Part60–69 (good)70+ (excellent)
1Well-structured database, good specification and data model; normalised schema (2NF) with ERD.Excellent, original, researched solution; data model normalised to 3NF with ERD.
2Good structure of triggers, views and functions that solve the problem and cover the requirements.Excellent, original and researched; very well written report; all tools included.
3Well-structured Python–SQLite Tkinter connection; validation and encryption; good testing plan; good XML and image storage; good-quality demo video.Excellent validation and encryption; excellent XML and image storage (including converting images back); testing plan with suggested solutions; innovation; good-quality demo video.

Lower bands mention, among other things, saving images “but not converting back” (50–59) and poor or missing XML, image storage, encryption or testing. Read the full descriptors in the brief.

Submission requirements

Submit two files

  1. The report as a single PDF: title page, contents page, page numbers, about 2,000 words, with screenshots of input/output, user interaction and evidence that the requirements are met.
  2. One ZIP file containing your Python code file(s), the SQLite database, the XML file(s), a README.md (how to run the application and the database) and a demo video of 1–2 minutes.

Demo video penalties (from the brief)

If the demo video fails to upload, your final grade is reduced by 10%. The Part 3 grade descriptors also list a 7% reduction for a video uploaded without sound, and a 5% reduction for a very basic video with sound. Check that your video plays, has audio and stays within 1–2 minutes before you submit.

Late work and extenuating circumstances (summary)

Work submitted up to 7 calendar days late is capped at 40% if it passes. Later than that it counts as a non-submission (zero). Referred work must be on time. You can self-certify for up to two assessment dates per semester for a 7-day extension; otherwise apply for extenuating circumstances with evidence. Check the full regulations linked in the brief.

Testing guidance

Official Both Part 2 (database) and Part 3 (application) include “Testing and reviewing” (5 marks each). The 70+ descriptor asks for a testing plan with suggestions of solutions.

Recommended Write a test plan with at least 7 tests per part and record evidence (screenshots) for each. Use this layout:

No. / categoryTest nameExpected resultPassed (Y/N)Review / action taken
1 · FunctionalInsert an order for a customer who does not existRejected with “FOREIGN KEY constraint failed”; no row addedYForeign keys enabled on every connection
2 · FunctionalAFTER INSERT trigger reduces stockStock for the product falls by the quantity orderedNTrigger used a fixed value; rewritten to use NEW.quantity; retested: passed
3 · ValidationRegister with e-mail “abc”Message “Enter a valid e-mail”; nothing savedY—
Functional
Does each feature meet its business requirement?
Integration
Do the GUI, the database and the XML file work together correctly?
Acceptance
Does the system satisfy the client requirements you listed in Part 1?
Smoke
Does the application start and do its basic actions without crashing?
Non-functional
How well does it work: speed, file size, usability, security?

Points to confirm with the module leader

These are gaps or ambiguities in the brief itself. Ask rather than guess:

  • The brief’s Learning Outcomes and Living CV sections are blank, and it gives a font size but no font name.
  • The brief says “SQLite Server” and, for images, “SQL Server database”. The module uses SQLite throughout, which is serverless; read these as “SQLite database”.
  • The Part 3 Tkinter application criterion has no separate mark allocation; the listed Part 3 items add up to 25.
